# Support Policy

## Public support channel

Use [GitHub Issues](https://github.com/Shiro7/vibe-product-os/issues) for
installation problems, reproducible defects, command behavior, and
documentation gaps. Search existing issues before opening a new one.

Include the package version, embedded framework version, operating system,
Node.js version, exact command, expected and observed results, minimal
reproduction steps, and non-sensitive evidence.

Do not include credentials, private keys, confidential project artifacts,
regulated data, or unpublished security details. Follow `SECURITY.md` for a
suspected vulnerability.

## Public pilot feedback

The `0.1.x-pilot` line is open for public use and testing. GitHub Issues may
also be used for workflow feedback, usability observations, documentation
suggestions, and reproducible project-integration results. Mark assumptions,
avoid confidential project content, and explain whether the result came from
P1, P2, or P3.

## Pilot response policy

- Initial response target: five business days.
- Support is best-effort during the `0.1.x-pilot` line; this is not a paid SLA.
- Resolution time depends on severity, reproducibility, release boundaries,
  and Product OS Authority approval where required.
- Only the latest published `pilot` version receives routine support.

The Product OS Authority owns support policy, prioritization, release changes,
and official product decisions. An issue or pull request does not approve its
own change or create an official Product OS release.
